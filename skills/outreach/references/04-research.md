# 04 — 리서치 & 개인화 재료 (발굴 우선순위)

<!-- 원본: salesfactory-plugin skills/salesfactory/references/04-research.md — sales-copilot 통합판 -->

각 후보 회사를 조사해 **개인화 후크(hookContext)**를 만든다. 이게 메일 응답률을 가른다 — 그리고 국내 트랙에선 **1:1 개별 작성의 근거**이기도 하다(08 판정 조건 ①). 이미지팩토리 brief-extractor의 발굴 우선순위를 그대로 계승한다.

## 발굴 우선순위 (brief-extractor SYSTEM_PROMPT 정본)

후보 회사에서 후크가 될 재료를 이 순서로 찾는다:

1. **수치·증거** — 리뷰 평점, 판매량, 수상, 투자유치액, 성장률, 채용 규모
2. **오퍼·이벤트** — 신제품 출시, 캠페인, 확장, 신규 지점
3. **차별 기능·포지션** — 그 회사만의 특징, 최근 방향 전환
4. **감성·맥락** — 대표 인터뷰, 미션, 업계 이슈 대응

상위 2~3개를 조합해 "이 회사에게 왜 지금 연락하는가"의 근거로 쓴다.

## 철칙 — 근거 없는 개인화 금지

- **본문에 있는 것만.** 회사에 대해 확인 못 한 것을 지어내면 들키고 역효과. 확인된 사실 + 출처를 hookContext에 남긴다. **사실(출처 있음) vs 추론(가설)을 구분**하고, 추론은 단정하지 않는 표현으로만 쓴다.
- 재료가 빈약하면 억지 개인화 대신 **업종 공통 후크**를 구체화("성형외과 마케팅에서 요즘 가장 어려운 게 네이버 플레이스 상위 노출인데…") — 그래도 사실 기반으로. 단, 업종 공통 후크만으로는 국내 트랙의 1:1 개별 작성 판정(08 ①)을 채우기 어렵다 — 상대 회사명·구체 접점이 본문에 실명으로 들어가야 한다.

## hookContext 구조

```
{
  company:    회사명
  hook:       개인화 후크 1~2문장 (위 우선순위로 발굴)
  sources:    [근거 URL...]   ← 반드시 출처. 없으면 그 hook 쓰지 마라
  confidence: high | low       ← low면 후크 대신 업종 공통으로
}
```

## 리서치 깊이 2단 (필수 — 비용·시간 관리)

깊은 리서치는 후보 1건당 상당한 웹검색·판독을 쓴다. 전량을 깊게 조사할 수 없다(Claude 사용 한도).

1. **전량 값싼 패스**: ICP 적합성 + 연락처 실재만 빠르게 확인. 부적합·연락불가 후보를 여기서 걸러낸다.
2. **상위 N건 깊은 패스**: 통과한 후보 중 상위 N개만 hookContext를 깊이 판다.

이건 타협이 아니라 설계다. 리서치를 발송 페이스에 맞춰 분산하면 사용 한도와 발송 위생이 동시에 관리된다(07).

## LLM vs 결정론 경계 (이미지팩토리 enrich.ts 원칙: "LLM은 톤·개인화·분류만")

내부 콜드메일 시스템의 확립된 원칙 — **판단은 LLM, 운영 로직은 결정론.**

- LLM(Claude)이 하는 것: 회사 리서치, 후크 발굴, 개인화 문안, 답장 의도 분류.
- 결정론 코드가 하는 것: locale 판정, 호칭 조립, 중복 제거, 카운터, 발송 게이트(전부 `scripts/normalize_contact.py`·`scripts/state.py` + `apps-script/coldmail/`).

## ⚠️ 이식 금지 — 이름으로 국적·민족 추론

내부 코드의 `KOREAN_SURNAMES` / `looksLikeForeignName`(성씨 로마자로 한국인 여부 추론)은 **이식하지 않는다.** 성명에서 민족·국적을 추론해 저장하는 것은 AUP 보호속성 프로파일링 + 개인정보보호법 민감정보 축에 걸린다. locale·언어는 **회사 소재국·사이트 언어**로만 판정한다(05).
