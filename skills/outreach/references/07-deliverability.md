## 타깃 = 회사 도메인 Workspace (영업은 회사메일로 한다)

콜드메일 영업은 개인 Gmail이 아니라 **회사 도메인 = Google Workspace**로 한다. 이게 기본 전제다.

| | Google Workspace (기본) | consumer @gmail.com (예외) |
|---|---|---|
| 발송/일 | **1,500통** (도메인 내부 수신자면 2,000) | 100통 |
| 트리거 실행시간/일 | 6시간 | 90분 |
| Gmail read/일 | 50,000 | 20,000 |
| 지속가능 신규/일 (팔로업 누적 포함) | **300~370명** | 20~25명 |

- **할당량은 병목이 아니다.** Workspace 1,500/일이면 하루 300 신규도 단일 계정 여유. 병목은 **도메인 평판·스팸신고율**로 넘어간다.
- 회사 도메인은 이미 SPF·DKIM이 붙어 있어 개인 무료메일보다 **도달률 우위** + 발송 평판이 있어 신규 도메인 웜업이 불요.
- 상수는 `ACCOUNT_TYPE` 기본 `workspace`. 온보딩에서 개인 Gmail이면 consumer로 강등(09).

## 진짜 리스크는 할당량이 아니라 "회사 본진 도메인 평판" (핵심)

**콜드메일을 회사 본진 도메인으로 쏘면 잘못될 때 회사의 정상 업무메일까지 스팸 취급**받는 게 유일한 실질 리스크다. 그래서 **발송 도메인 격리**가 핵심 권고다:

| 방식 | 설명 |
|---|---|
| **별도 도메인**(권장) | 콜드메일 전용 새 도메인 구입 → 본진과 완전 격리. 사고나도 본진 업무메일 안전. 연 1~2만원. 새 도메인은 평판 0이라 **램프업(=웜업) 필요** |
| **본진 그대로** | 추가 비용·세팅 0, 기존 평판 즉시 활용. 대신 **콜드메일 사고 = 회사 업무메일 도달률 타격** 위험 |
| **서브도메인**(`mail.회사.com`) | 중간. 본진과 평판 일부 공유 → 위험 잔존 |

**사용자가 선택**하되, "본진 그대로 소량"으로 시작해 볼륨을 늘릴 때 별도 도메인으로 졸업하는 게 자연스럽다.

## 램프업 = 웜업 (별도 웜업 절차 없음)

| 단계 | 메일박스 | 일 발송 |
|---|---|---|
| 가볍게(기본) | **회사 도메인 메일 1개** (기존 평판 → 웜업 불요) | 신규 ~50 |
| 증량 | 동일 | 바운스·신고율 보며 자동 증량, ~150 |
| 확장 | 별도 전용 도메인(격리) + 메일박스, SPF/DKIM/DMARC | ~300+ |

- 신규 **전용** 도메인만 램프업 필요(평판 0에서 시작). 회사 본진 도메인은 소량 시작 즉시 가능.
- DNS 지원 경계: 플러그인은 SPF/DKIM/DMARC **값을 계산해 "이 세 줄을 DNS에 붙여넣으세요"까지** 만들어준다(결정론). 등록업체 로그인·레코드 추가 클릭은 **사용자 몫**(대리 설치 안 함).

## 발송 게이트 (전부 코드 강제, 상향 불가 — apps-script/coldmail/Code.gs)

- 일 상한 = `DAILY_SEND_CAP[ACCOUNT_TYPE]`과 `DAILY_TARGET`의 MIN (Workspace 1,500 / consumer 100)
- 발송 페이싱 + 업무시간대·주말 제외 (Workspace 5분 페이싱 여유, consumer면 10~15분)
- **dry-run 기본값.** `LIVE_SEND`를 사용자가 명시적으로 켜야 실발송 — 첫 실발송은 반드시 내 주소 테스트 1건(09·W2d)
- **바운스율 2% 초과 → 자동 감속, 계속 → 정지.** 스팸신고율 0.1% 목표(Gmail 0.3% 요건)
- 발송 전 이메일 검증(있으면) — valid만, catch-all/unknown 제외

## Google 계정 리스크

실계정 반복 자동화는 남용 탐지로 차단된다. 테스트는 소량·본인 주소. **멱등키 필수**(draftId에 타임스탬프를 넣지 마라 — 재시도 시 중복 발송). scope는 `gmail.send`(민감)로 — `mail.google.com`(제한) 금지, OAuth 하드블록 회피.
